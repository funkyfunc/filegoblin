# Architecture Decision Records (ADR)

*A lightweight log of design decisions made during the development of filegoblin to capture intent, without being overly burdensome.*

---

## 2026-02-22: Stripping Web Links by Default
**Context:** When parsing HTML via `WebGobbler`, the extracted `href` attributes create significant context bloat and noise for LLM models. For human readers (e.g., using `--flavor human` or `--full`), the links are equally useless since the output is no longer an interactive website but static Markdown.
**Decision:** All HTML links `<a>` will be aggressively flattened into plain text (e.g., `[Link Text](path)` becomes simply `Link Text`) before the Markdown conversion step, regardless of the `--full` or flavor flags.
**Status:** Accepted

## 2026-02-22: System Proxy Ingestion
**Context:** The tool will be used in corporate environments where outbound network traffic must flow through HTTP/HTTPS proxies. For safety and predictability, we must ensure these are respected.
**Decision:** `reqwest::blocking::Client` inherently reads standard environment variables (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`) by default. We will simply rely on this robust behavior without bloating the codebase with manual proxy logic, but will add explicit `println!` logging into `route_and_gobble`'s URL fetcher so users have immediate visibility that their corporate proxy is being actively used.
**Status:** Accepted

## 2026-02-22: Extracting System Blueprint to ARCHITECTURE.md
**Context:** The founding research docs contain massive amounts of deep technical justifications (Rust vs Go, WASM OCR over Tesseract, Wayland Clipboard protocols). `PRD.md` is meant for *what* the tool does, and `README.md` is for *how* to use it, leaving the *why* undocumented.
**Decision:** Created a new root-level file `ARCHITECTURE.md` to permanently capture the 5 core pillars of the `filegoblin` system based on the initial R&D specs.
**Status:** Accepted

## 2026-02-22: Output Routing & Splitting Philosophy
**Context:** During the implementation of Phase V (`--horde`), the application needed a way to handle the massive output streams generated by crawling entire web domains or local directories. We debated using an `--out-dir` flag to redirect streams to a custom named folder, or writing the massive stream to a single auto-generated file.
**Decision:** We adopted a strict UNIX-philosophy stance. `filegoblin` will output everything to `stdout` by default, deferring file aggregation to standard shell piping (e.g. `fg --horde > output.md`). However, because large LLM contexts sometimes need compartmentalization, we introduced a single, zero-configuration `--split` boolean flag. This flag suppresses `stdout`, auto-derives a directory name from the target (e.g., `./target_gobbled/`), and maps the internal nodes as discrete `.md` files without requiring the user to wrangle directory names.
**Status:** Accepted

## 2026-02-23: Tiered Privacy Shield Architecture
**Context:** The Phase IV specification requires zero-dependency, local-only PII redaction. Linking a standard ONNX Runtime would bloat the binary beyond the 50MB constraint.
**Decision:** The Privacy Shield (`--scrub`) is implemented as a 3-tier engine. The "Sentinel" pass uses the `aho-corasick` crate for immediate <100ms algorithmic redaction. The "Trigger" uses Shannon Entropy (`sliding_features`) to isolate ambiguous windows. Finally, the "Refiner" neural pass uses a pure-Rust inference engine (`candle-core`) loading zero-copy memory-mapped `safetensors`. This fulfills all structural constraints without sacrificing accuracy. 
**Status:** Accepted

## 2026-02-23: Redaction String Standardization
**Context:** Following the implementation of the Privacy Shield engine, the default replacement string for redacted entities was initially set to `[CONFIDENTIAL]`. However, this deviated from standard industry nomenclature and user expectations for sanitized documents.
**Decision:** Updated the engine and associated tests to use the string `[REDACTED]` for all PII and secret scrubbing. This aligns with standard redaction terminology and provides a clearer, universally understood visual cue that information has been explicitly removed for privacy reasons.
**Status:** Accepted

## 2026-02-24: Hybrid OCR Architecture for Zero-Dependency Performance
**Context:** The Phase VIII Image OCR implementation required a pure-Rust or statically deployable engine without external C-bindings. Testing revealed pure-Rust CPU math via `ocrs` and `rten` took 200ms-2s per image—functional, but sluggish for a CLI tool.
**Decision:** Implemented a Hybrid "Native Escape Hatch" Architecture. On macOS, `filegoblin` uses pure-Rust `objc2` bindings to directly hook into Apple's Vision Framework, achieving instantaneous (<50ms) hardware-accelerated text extraction. On Linux/Windows, it conditionally compiles the `ocrs` engine using local `.rten` tensor weights as a fallback. This completely satisfies the zero-dependency mandate while unlocking maximum hardware performance where APIs are available.
**Status:** Accepted

## 2026-03-08: Adopting Heuristic Auto-Pruning with Context Fallbacks
**Context:** When users scrape massive targets and set `--max-tokens` limits, blindly truncating the output ruins the structural integrity of the prompt. We needed a way to intelligently prioritize data to maximize LLM relevance density.
**Decision:** Adopted a sequential pipeline. It first strips files based on a multi-tiered precedence mapping (`.gitignore`, then extension-based ranking). If the repository still exceeds the budget, it selectively hollows out implementation logic using `tree-sitter` ("Skeletonization"), preserving only function signatures and docstrings to provide dense mapping without massive token waste.
**Status:** Accepted

## 2026-03-08: Tantivy BM25 over Native ONNX for Search
**Context:** Implementing a self-contained RAG (Retrieval-Augmented Generation) layer inside CLI contexts required deciding between dense embeddings using `candle-core` / `tract` (e.g., tracking a quantized 22MB MiniLM model) and a pure-text index.
**Decision:** Selected `tantivy` (BM25 lexical search) over neural embeddings. The inverted index requires zero model weights, adds almost negligible binary bloat, and provides sub-10ms ephemeral searches. For highly specific technical code querying (e.g. searching for specific struct names), lexical matching out-competes generic semantic associations. We bridge the semantic gap manually via snake_case tokenization and synonym expansions.
**Status:** Accepted

## 2026-07-05: Reverting Experimental TOON Encoding and Optimizing Caching Alignments
**Context:** An experimental lossy TOON encoder for JSON was added, along with several caching optimizations inspired by research papers (such as inserting `<cache_control>` text for Anthropic and stripping trailing whitespace for GPT). However, TOON encoding was deemed an unnecessary fad, and the caching optimizations introduced issues (such as raw text `<cache_control>` tags which Anthropic does not support parsing inside the prompt text, and destructive stripping of trailing whitespace which broke Markdown line breaks). Furthermore, unused dependencies (`simd-csv` and `memchr`) were added to `Cargo.toml`.
**Decision:** Deleted the TOON encoder entirely and removed the `--compress-json` flag. Replaced the naive `<cache_control>` tag insertion and destructive whitespace stripping with deterministic alphabetical document sorting for all flavors (preserving `_tree.md` at the absolute beginning of the bundle). Removed the unused `simd-csv` and `memchr` dependencies, and updated the aggressive compression pipeline to restrict statistical token filtering to prose contexts (`language.is_none()`) to prevent source code corruption.
**Status:** Accepted


## 2026-07-13: Phase-6 Audit Cleanup — Honest Privacy, Web/Archive/WASM Hardening, Dead-Code Removal
**Context:** A principal-architect audit found that two feature builds (`web`, `tui`) did not compile (so `all-features` release binaries were broken), the default streaming path silently dropped LLM flavor formatting, several production parsers returned fabricated content on read errors, the Privacy Shield's "neural" tier was a hardcoded mock, and the codebase carried ~12 unused dependencies plus a PageRank pruner whose substring-based dependency heuristic produced garbage edges and was never wired into budgeting.
**Decision:**
- **Privacy Shield:** Deleted the mocked SLM refiner and its inert tokio semaphore. Kept a two-tier honest engine: deterministic Aho-Corasick + regexes (now including AWS/GitHub/OpenAI/JWT secret prefixes) and a Shannon-entropy tier that redacts *unbroken* high-entropy tokens (whitespace-free windows) to avoid nuking prose. Fixed a char-boundary panic on multibyte input. Removed all "Distil-PII-1B" claims from docs.
- **Network:** Added `src/net.rs` with hardened reqwest clients (30s timeout, 10 MiB response cap, and an SSRF-guarding redirect policy that refuses loopback/private/link-local/metadata hosts). Correct User-Agent derives from `CARGO_PKG_VERSION`.
- **Archives:** Added uncompressed-size (2 GiB) and entry caps, an explicit zip-slip guard, and a nested-archive guard to stop zip-quine recursion.
- **WASM:** Added fuel + memory `StoreLimits`, cached the `Engine`, and stopped implicit extension dispatch from auto-executing `./plugins/*.wasm` in the CWD (home dir only; `--plugin` still allows CWD).
- **git:** `--git-diff` refs starting with `-` are rejected (option-injection guard); shelling moved to `src/git.rs`.
- **Removed:** `petgraph`+PageRank, `compression-prompt`+`stop-words`+the `aggressive` compression level, dead `credentials.rs`, the unimplemented `--lang` flag, `scratch/` scripts, production mock fallbacks, and unused deps (`fst`, `sliding_features`, `safetensors`, `nojson`, `memmap2`, `nonzero_ext`, `urlencoding`, `base64`, `sha2`, `wasmtime-wasi`). `tokio` is now feature-gated to `web`/`ocr`.
- **Behavior:** `CodeGobbler` emits full content by default; `--extract symbols` is opt-in and Rust-only. `--include`/`--exclude` use real globs (`globset`). The streaming default path now applies flavor formatting (fixing a regression); whole-output flags buffer.
- **Structure:** `gobble_local` decomposed into `walk.rs` + `git.rs` + a `parse_files` helper.
**Status:** Accepted

## 2026-07-14: Privacy Shield as a Product — Typed Rule Engine + Report/Gate/Config
**Context:** After the Phase-6 cleanup replaced the mocked PII tier with an honest deterministic+entropy engine, `--scrub` was still thin: a handful of secret shapes, an opaque `[REDACTED]` for everything, a false-positive-prone credit-card regex, and no operator-facing trust or scripting surface. The goal was to make the local, zero-telemetry scrubber genuinely useful — pipe a log through it, or gate a prompt on it before sending to a cloud LLM — while staying a single binary with zero model weights.
**Decision:** Rewrote `privacy_shield.rs` as a typed rule engine (`PiiKind` + `Match` + validated `RegexRule`s):
- Expanded detection: AWS/GitHub/OpenAI/Google/Slack/Stripe keys, JWTs, private-key blocks, `scheme://user:pass@host` connection strings, phone/IPv4/IBAN, plus the prior email/SSN. Numeric patterns are gated by validators — **Luhn** (credit cards), SSN area/group/serial range, IPv4 octet range, IBAN mod-97 — so we redact real values, not any digit run. Dropped the old keyword-word redaction (redacting the literal word "Passport" was noise). The Shannon-entropy tier remains as a whitespace-free catch-all, typed `SECRET`, and yields to any overlapping rule match.
- **Typed labels by default** (`[EMAIL]`, `[AWS_KEY]`, …) so a downstream LLM knows what was removed; `--scrub-style plain` restores `[REDACTED]`.
- **Audit report**: a value-free tally by kind printed to stderr after a run (`🛡️ Privacy Shield redacted N item(s): …`), backed by `Sync` interior counters on one shared shield that aggregates across the buffered (rayon) and streaming paths.
- **CI gate**: `--scrub-fail` makes the process exit 3 when anything is redacted (`gobble_app` now returns the redaction total; `main.rs` maps it to the exit code).
- **Config** (`scrub_config.rs`, serde_json): `--scrub-config <path>` or auto-discovered `./.filegoblin-scrub.json` supplies an `allowlist` (exact values never redacted; also `--scrub-allow`) and custom `patterns` (each redacted under its own `[NAME]` label; invalid regexes are skipped, not fatal).
**Status:** Accepted. Deferred: consistent pseudonymization (`[EMAIL_1]`), an optional local NER tier, and a `fg scrub` subcommand.

## 2026-07-14: Consistent Pseudonymization + JSON Extraction Contract
**Context:** Two follow-ons after the Privacy Shield productization. (1) Typed labels hide a value but also erase that the *same* value recurs — which a downstream LLM often needs (co-reference). (2) `--json` was an under-specified `{path,content}` array emitted in nondeterministic order on the streaming path, and a failed single-file extraction silently produced an empty array (looks like success) — poor as a machine contract for agents.
**Decision:**
- **`--scrub-style pseudonym`**: a third redaction style that replaces each value with a stable indexed placeholder (`[EMAIL_1]`, `[EMAIL_2]`, …). A `Mutex<PseudoInterner>` on the shared shield assigns one index per distinct (label, value) and reuses it everywhere, so consistency holds across every document in a run. Indices are assigned in reading order (replacements computed front-to-back, applied back-to-front).
- **`--json` as a stable machine contract**: records are now `{path, format, tokens, content}` — `format` is a coarse type label, `tokens` an LLM estimate — so an agent can extract one file and budget it in a single call. `--json` now routes through the buffered pipeline so output is deterministically alphabetically sorted (verified: identical across runs). Exit codes: `0` success, `4` when `--json` extracted nothing (distinguishes empty result from total failure), `3` for `--scrub-fail`. `gobble_app` returns a `GobbleOutcome { redactions, produced }`; `main.rs` maps it to the exit code.
**Status:** Accepted. Still deferred: an optional local NER tier and a `fg scrub`/MCP surface.

## 2026-07-18: Native Email (.eml/.mbox) and RTF (.rtf) Parsers
**Context:** Toward the "universal LLM translation tool" goal — point filegoblin at any messy real-world format and get clean text — two high-frequency gaps were email and RTF, both of which previously fell to the raw-plaintext fallback (RTF dumped control words; email dumped MIME headers/encoding). Rather than take a hard dependency on an external converter like pandoc (which would forfeit the zero-dependency single-binary identity, and which cannot even read PDFs), these were added as native pure-Rust parsers.
**Decision:**
- `EmailGobbler` (`parsers/email.rs`) via `mail-parser`: handles `.eml` and `.mbox` (splitting the mailbox on `From ` envelope lines and rendering each message). Emits a markdown header block (From/To/Cc/Date/Subject) plus the body, preferring `text/plain` and falling back to a minimal HTML strip.
- `RtfGobbler` (`parsers/rtf.rs`) via `rtf-parser`: lexes/parses RTF and returns the plain body text.
- Both are **always-on** parsers (not feature-gated), consistent with the other core formats.
- **`.msg` (Outlook) was intentionally dropped**: the `msg_parser` crate pulls a `tsify`/`gloo-utils` (wasm-bindgen/TypeScript-interop) dependency chain that bloats the binary against the lean identity. `.eml`/`.mbox` cover the overwhelming majority of real email; `.msg` can return later as a WASM plugin or behind a feature.
- `--json` `format` labels extended: `email`, `rtf`.
**Status:** Accepted.

## 2026-07-18: Architecture — one document type, magic-byte routing, HTML split from web
**Context:** Three seams blocked the "universal, agent-trustworthy converter" goal: (1) the parser layer spoke `(String,String)` pairs while everything downstream spoke `GobbleDocument`, so per-file metadata and parse errors were discarded (a failed parse vanished — "empty output looks like success"); (2) dispatch was a 13-arm extension `match` with no magic-byte detection, so renamed/extension-less files fell to raw plaintext; (3) HTML→markdown was trapped behind `--features web`, so parsing a local `.html`/`.epub` needed the whole network stack.
**Decision:**
- **`format.rs`** (new): a `Format` enum + `detect(path, header)` — extension-first, magic-byte fallback (`%PDF`, `{\rtf`, `PK`, gzip, PNG/JPEG/WebP, RFC822, HTML) — with `label()` for the JSON contract. `route_and_gobble` now returns `(Format, Result<String>)` and dispatches on `Format`. Renamed/extension-less files route correctly.
- **`GobbleDocument`** gains `format`, `bytes`, `error`; `gobble_local`/`parse_files`/`extract_archive` return `Vec<GobbleDocument>` (no more pair boundary or 6 reconstruction sites in routing). A failed parse is recorded as an error document (logged AND carried), surfaced in `--json` as an in-band `{path, format, error}` record; non-JSON output drops it. Exit code 4 already signals "nothing extracted".
- **HTML split from web:** `html2md` is now non-optional; `WebGobbler` moved to an always-on `parsers/html.rs` as `HtmlGobbler`; `epub.rs` and the HTML/EPUB route arms are always-on. The `web` feature is now purely network (reqwest/scraper/governor/robotxt/tokio + crawler/fetch/github). A default build parses local `.html` and `.epub`.
- Tracked for later (Phase 2): unify the buffered/streaming formatter paths; cache token counts; pass `ParseOptions` instead of `&Cli`; drop tokio (sync crawler).
**Status:** Accepted.

## 2026-07-27: Trust Layer — fail loudly, never silently succeed
**Context:** Audit findings showed the flagship path could no-op invisibly: the producer thread's error was discarded (`let _ = route_targets(...)` — a default build given a URL printed nothing and exited 0), `cargo install` produced a binary without web support (the cli crate had no passthrough features), `--flavor`/`--extract` were unvalidated strings silently falling back, and stdin auto-detection both broke `cat x | filegoblin` (clap required a path first) and hung/polluted runs spawned with an idle stdin pipe (phantom `-` target).
**Decision:**
- `gobble_app` keeps the producer `JoinHandle` and propagates its error after the channel drains; the ingestion thread can no longer fail invisibly.
- Exit code 4 ("nothing extracted") now applies to **every** output mode, not just `--json`. `stream_and_output` returns its produced-document count so the streaming path participates.
- The cli crate gained passthrough features (`web`/`ocr`/`wasm`/`rag`) with **`web` on by default** — "convert websites to markdown" is half the pitch; a plain `cargo install` must do it.
- `Flavor` and `ExtractMode` are clap `ValueEnum`s (defined in `cli.rs`, which `build.rs` includes, and re-exported via `flavors.rs`): typos are hard errors listing valid values, and variants appear in `--help`/completions.
- Stdin precedence: explicit paths win; stdin is only read when **no** paths are given. Broken stdout pipes (`filegoblin x | head`) exit 0 quietly.
- Fixed the tui crate's `web` feature compile (stale `parsers::web` path), restoring `--all-features` builds.
**Status:** Accepted.

## 2026-07-27: DOM-Based HTML Extraction (readability-lite)
**Context:** `HtmlGobbler` was string surgery (`String::find`/`replace_range`): first-`<article>`-only (multi-article pages lost everything else), `<header>` stripped wholesale (destroying titles), every hyperlink URL deleted, an "accounts.google.com / sign in + google" substring bail that hard-failed ordinary articles, and O(n·k) scans. `scraper` (html5ever) was already a dependency, used three lines away in the crawler.
**Decision:** Rebuild on the DOM (`scraper` promoted to always-on). Selection: every `<main>` → every `<article>` → best text/link-density block candidate, guarded (if the winner holds <60% of the page's text, fall back to `<body>` — content is never dropped). Noise: nav/aside/footer/form/script/style detached; link-farm blocks (≥85% link density) pruned even inside `<main>`. Links/images keep URLs, resolved absolute against the source URL. Output carries YAML front-matter (`title` from `<title>`/`og:title`, `source` URL). `html2md` wrapped in `catch_unwind` (one malformed page can't kill a horde run); its raw-`<img>` passthroughs and space-padded table rows tidied post-hoc. JS-gated detection is DOM-based (<10 words + scripts); the Google-substring bail is gone. `fetch_url` decodes non-UTF-8 via Content-Type/meta charset (`encoding_rs`) instead of hard-failing.
**Status:** Accepted. Deferred: sibling-content merge around the chosen candidate; per-site extraction rules.

## 2026-07-27: Conversion Quality — docx markdown, one table dialect, PDF cell splitting
**Context:** docx flattened every paragraph to `raw_text()` (no headings/lists/emphasis/links). Sheets ignored the real header row and emitted `Col A:` letters while PDF/docx tables used header names — two dialects for the same concept. The PDF fixture output "Net ProfitGrowth: …; Col 4: …" — a header-merge bug the old test asserted as correct (oxidize-pdf's `preserve_layout` merges fragments whose gap its glyph-width estimate underestimates, so one fragment straddles a column boundary).
**Decision:** docx maps Heading/Title styles to `#` levels, numbering to (nested) `-` lists, bold/italic runs to emphasis, and hyperlink rids to real URLs via the reader's rels. Sheets treat row 1 as headers (`Headers:` line + `Row N: Header: val;` records; empty header cells fall back to column letters; malformed CSV rows are skipped and counted, not fatal). PDF tables assign cell text from fragment geometry in our code: fragments straddling column boundaries are split at the boundary-proportional character, snapped to a space or case seam. Empty/encrypted/pageless PDFs now error instead of returning `Ok("")`.
**Status:** Accepted.

## 2026-07-27: Golden-File Testing (insta + assert_cmd)
**Context:** The product is its markdown output, yet the output surface had zero tests: `formatters.rs` (875 lines, every output mode) untested, 3 of 4 committed fixtures unreferenced, flavor regressions (human≡gemini, breadcrumb leaks) invisible.
**Decision:** `crates/cli/tests/golden.rs` runs the real binary end-to-end: one snapshot per format (pdf/docx/csv/pptx/ipynb/html) over real fixtures (new: `quarterly_report.docx` — hand-authored OOXML, `saved_article.html`), one per flavor, one horde run over a controlled directory, plus behavioral contract tests (exit 4 on nothing-extracted, hard error on bad flavor, bare-pipe stdin, paths-beat-stdin, JSON record shape, `--scrub` via stdin). `walk_tree` sorts by file name so runs are deterministic. Snapshot changes are reviewed with `cargo insta review`.
**Status:** Accepted. Known-and-documented by snapshots (deliberately unfixed here): the anthropic flavor double-wraps (`FILE_START` breadcrumb inside `<file>`), `gemini` ≡ `human`.

## 2026-07-27: Simplification — remove flavors, --watch, --cost
**Context:** Post-audit scope cut, per the owner's direction. The four `--flavor`s had collapsed in practice: `gemini` was byte-identical to `human`, the `anthropic` template double-wrapped the whole bundle instead of per-file tags, and the `FILE_START` breadcrumb leaked into every flavor anyway — four names for ~1.5 behaviors, threaded through every formatter path. `--watch` reimplemented `watchexec`/`entr` (~70 lines + the `notify` dependency in two crates, and it skipped the exit-code contract). `--cost` was a hardcoded USD price table guaranteed to go stale. The TUI and clipboard flags stay — they are actually used.
**Decision:** One output format: clean markdown with `// --- FILE_START:` breadcrumbs (what `human` already emitted). `flavors.rs`, `cost.rs`, `--flavor`, `--watch`, `--cost` deleted; `notify` dropped from both crates; `gobble_app`/formatter signatures lose the flavor parameter. The buffered stdout path also drops its stray `\n---\n` prefix, so buffered and streaming output are identical (modulo one trailing newline the streaming path cannot trim). Watching is a shell one-liner (`watchexec -- filegoblin …`); cost math belongs in the consumer.
**Status:** Accepted. If model-specific framing is ever wanted again, it should be a post-processing template over the `--json` contract, not a parameter threaded through every formatter.

## 2026-07-29: Docs Diet — README + ADR are the only load-bearing docs
**Context:** 26 markdown files (~3,600 lines of prose for ~7,000 of Rust) with four overlapping vision docs, and several confidently stated things that were false (ARCHITECTURE.md's ONNX PII model and wl-clipboard-rs, PRD.md's flavor templates and `--skeleton` flag, README's phantom build.rs asset fetcher, QA scripts pointing at a `./src/` dead since the workspace split). Agents read these files and trust them; wrong docs are worse than no docs.
**Decision:** Deleted `PRD.md`, `NORTH_STAR.md`, `ARCHITECTURE.md`, `implementation-notes.md`, `docs/UX.md`, `docs/ROADMAP.md`, `docs/instructions/`, `docs/agent_context/QA_PROMPT.md`, and `.agents/` (git history keeps them). NORTH_STAR's essence became a 5-bullet Philosophy section in the README. The load-bearing set is now: **README.md** (what/how), **docs/ADR.md** (why/history), `GEMINI.md` (agent standard, rewritten to match reality), `docs/agent_context/` (ephemeral session state), and `docs/research/` (clearly-labeled read-only archive). Also purged 15.7 MB of committed binary weights: the tesseract WASM core (referenced by zero code since the ocrs pivot) and the two `.rten` models (downloadable artifacts, not source) — `just get-brains` now fetches the correct ocrs models and `.gitignore` keeps them out.
**Status:** Accepted. Rule going forward (encoded in GEMINI.md §5): no new top-level docs; feature truth lives in README, decision history lives here.

## 2026-07-30: PDF engine — pdf_oxide, with OCR by default on macOS
**Context:** Two audit gaps converged: scanned PDFs (a huge share of real-world PDFs) produced only an error, and the `ocr` feature had never built (it declared `candle-core`+MKL, referenced by zero code) with weights loaded from a CWD-relative path. Studying the sibling `scry` repo led to its PDF crate `pdf_oxide`, which ships what we'd otherwise hand-build: native markdown conversion (headings, pipe tables, reading-order strategies, hyphenation), a 12-signal per-page scanned-vs-text classifier (`classify_page` — image-area ratio + text coverage + garbled/invisible-text ratios, not naive chars-per-page), and embedded-image extraction. `oxidize-pdf` also dragged `rusty-tesseract` (a tesseract shell-out) into the tree, contradicting the zero-dependency identity.
**Decision:** Swap `oxidize-pdf` → `pdf_oxide` (default features). Per page: `classify_page`, then `to_markdown` for text pages; for `Scanned` pages, pull the **largest embedded image** (the scan itself — no rasterization) and OCR it. **macOS OCR needs no feature flag**: Apple Vision via the already-unconditional `objc2` deps; `--features ocr` now gates only the Linux `ocrs`/`rten` path (weights via `$FILEGOBLIN_OCR_DIR` / next-to-binary / `./assets`) and the Windows OCR API. Vision observations are ordered by top-Y sort + anchored line clustering (a pairwise |Δy| comparator is intransitive and can abort — lesson lifted from pdf_oxide's own docs). Hybrid (`ImageText`) pages get native text plus a quoted "text from embedded image" block. Scanned pages with no OCR available emit a visible marker, and an all-scanned document with no OCR errors actionably. `candle-core` deleted; the custom column-splitting table code from 2026-07-27 is superseded by pdf_oxide's converter. New fixture `test_assets/scanned_report.pdf` with a macOS-gated OCR test.
**Status:** Accepted.

## 2026-07-30: Markdown pipe tables everywhere (supersedes Sequence of Records)
**Context:** pdf_oxide's converter emits standard markdown pipe tables. Keeping "Sequence of Records" in the other parsers would have reintroduced a two-dialect split — and the SoR rationale (LLM 2D-attention concerns from the original PRD) predates models that read pipe tables fine, while the product goal is explicitly *clean markdown*.
**Decision:** Every parser (sheets, docx, pptx, OpenDocument, PDF) emits pipe tables: source row 1 is the header row, cells escape `|` and newlines. The golden suite caught a doubled-trailing-pipe separator bug in the first implementation — exactly the regression class it exists for.
**Status:** Accepted.

## 2026-07-30: URL routing by Content-Type; coverage and polish
**Context:** The single-URL path assumed every response was HTML (mangling raw markdown/JSON, corrupting binaries); `api.github.com` matched the `ends_with("github.com")` clone heuristic; email HTML bodies went through a naive tag-stripper; PPTX dropped speaker notes and trusted filename numbers for order; `.odt`/`.odp` were unreadable; legacy `.doc`/`.ppt` and extensionless zips dumped binary garbage as "plaintext"; html2md emitted setext headings.
**Decision:**
- `fetch_url` returns bytes + media type; routing: HTML (declared or sniffed) → DOM extractor; textual types → passthrough; anything else → temp-staged through the magic-byte parser pipeline, so `filegoblin https://…/paper.pdf` behaves like a local file. GitHub cloning triggers only on real `github.com/owner/repo` URLs.
- Email: genuine text/plain parts preferred; HTML-only bodies convert through `HtmlGobbler` (full mode); attachments listed by name. (mail-parser's own silent HTML→text down-conversion is bypassed.)
- PPTX: slide order from `presentation.xml` `sldIdLst` resolved through rels (filename numbers are only a fallback); speaker notes emitted per slide with digit-only placeholder lines filtered.
- New `OpenDocGobbler` (`.odt`/`.odp`): headings with outline levels, nested lists, pipe tables, per-slide sections — one quick-xml walker for both.
- `Format::LegacyOffice` (OLE magic `D0CF11E0…` or `.doc`/`.ppt` extension) errors actionably ("re-save as .docx/.pptx"); `.xls` stays with calamine which reads it natively.
- Archives: interception is by detected format (magic), `extract_archive` sniffs PK/gzip when the extension lies, and an archive met *inside* a walk reports an honest in-band error instead of binary garbage.
- `tidy_markdown` converts setext heading underlines to ATX.
**Status:** Accepted.

## 2026-07-30: No secrets blocklist — the user decides what's sensitive
**Context:** The "radioactive files" filter (a hardcoded blocklist: `.env*`, `id_rsa`, `*.pem`, `.ssh/`, …) claimed "never ingest secrets, no matter what the flags say" — but only ran on the directory-walk path. `filegoblin .env` named directly ingested everything, silently. A guarantee that holds on some code paths is worse than no guarantee: users calibrate their behavior to the claim. The list was also inherently incomplete (no `.netrc`, `.npmrc`, `*.key`, …) and Unix-shaped.
**Decision (owner call):** Get out of that business entirely. The blocklist and filter are deleted. filegoblin converts **exactly what you point it at**; deciding what's sensitive belongs to the user, via three honest tools: the walker respects `.gitignore` (where real secrets usually already live), `--exclude` globs filter anything else, and `--scrub` redacts PII/secrets in what does get converted (unchanged — including `--scrub-fail` as a CI gate). The README states the non-promise explicitly.
**Also, found while verifying the new policy:** the entropy tier had a masking bug — windows merged across newlines (`look_back` bridging whitespace), welding independent secrets on adjacent lines into one span that was then dropped wholesale for overlapping any rule match. Net effect: an email on line 2 silently unprotected the AWS secret key on line 1. Entropy windows now merge only within an unbroken token (never across whitespace); regression test `adjacent_secrets_do_not_mask_each_other` covers it. And the zip bomb guard now enforces the cap on bytes *actually decompressed* (`take(remaining+1)` around the writer) instead of trusting the entry's declared size, which is attacker-controlled metadata. First-ever tests for `archive.rs` cover the cap and a normal extraction; the tar path already bounded writes by header size (documented in place).
**Status:** Accepted.

## 2026-08-02: MCP stdio server (`--mcp`)
**Context:** Terminal agents can use the CLI directly, but GUI clients (Claude Desktop, most MCP apps) cannot shell out — and MCP directories are a distribution channel. The `rmcp` SDK drags tokio/tracing/schemars into a crate whose tokio is deliberately optional.
**Decision:** Hand-rolled newline-delimited JSON-RPC 2.0 over stdio (`core/src/mcp.rs`, ~200 lines on serde_json — zero new deps). Tools-only server: `initialize` (version allowlist echo, newest fallback), `ping`, `tools/list`, `tools/call` with one `convert(source)` tool; notifications ignored; unknown method → -32601; bad JSON → -32700; batch → -32600 (removed from MCP 2025-06-18); stdin EOF / broken pipe → clean exit. Conversion failures are in-band `isError:true` so the model sees them. New `gobble_to_string` runs the normal producer pipeline but returns markdown instead of writing stdout (MCP stdout carries only protocol messages; all diagnostics were already stderr). Directories get horde mode; URLs never do (no unbounded crawls inside a tool call). E2e test drives the real binary through the full handshake and asserts every stdout line parses as JSON.
**Status:** Accepted.

## 2026-08-02: `--browser` — JS pages via the user's installed Chrome
**Context:** The static fetcher honestly fails on SPAs/JS-gated pages. Research: CDP crates are disqualified (chromiumoxide generates ~60K LOC at build; attaching to a running logged-in Chrome died in Chrome 136), while Chrome's own `--headless=new --dump-dom` implements the load-wait + virtual-time settle loop (`pauseIfNetworkFetchesPending` ≈ network-idle) natively.
**Decision:** Shell out to a discovered browser ($FILEGOBLIN_BROWSER/$CHROME_PATH/$CHROME → per-OS app paths/PATH, chrome-launcher ordering) with `--headless=new --dump-dom`, fresh temp profile (Chrome refuses shared profiles; also: no cookie leakage — documented limitation: no logged-in sessions), `--timeout` for load + `--virtual-time-budget` for settle, no `--no-sandbox` ever. **Strictly opt-in** (`--browser`): the browser bypasses net.rs's SSRF redirect guards, so we never silently escalate from static fetch to executing remote JS; the JS-gated error (now a typed `JsGated` marker) suggests the flag. Hard-won reliability details: new headless sometimes writes the full dump then hangs at shutdown (crbug 327458826) — the collector watches for `</html>`-terminated, 1s-stable output and kills Chrome itself, so the flaky hang costs ~1s instead of a timeout; do NOT setpgid Chrome on macOS; stdout drains on a thread (pipe deadlock); Chrome's exit code is ignored (unreliable) in favour of validating the DOM. URL extraction failures now also emit an in-band failed document instead of being silently dropped.
**Status:** Accepted. Deferred: `--browser` for `--horde` crawls (per-URL ~1s launch cost wants a CDP backend), shadow-DOM piercing.

## 2026-08-02: Conversion cache (`~/.filegoblin/cache`)
**Context:** Agents re-read the same sources in loops; URL fetches, OCR, and (upcoming) transcription are the expensive steps. Local parses are cheap and not worth caching.
**Decision:** Content-addressed best-effort cache at `~/.filegoblin/cache/<kind>/<sha256>` (`core/src/cache.rs`, sha2 added — first direct hashing dep). Kinds: `url` (keyed by URL, 15-min TTL since remote content changes, opportunistic sweep of entries older than 4×TTL) and `ocr`/`transcript` (keyed by input-bytes hash [+model], never stale). Writes are atomic (`.part`+rename) and silent-on-failure — the cache is never load-bearing. `--no-cache` disables read+write for a run (process-wide AtomicBool set at entry). Wrap points: `fetch_url` (simple two-header-line + raw-bytes wire format for FetchedBody) and `ocr_image_bytes`. Measured: repeat URL fetch 2.2s → 13ms.
**Status:** Accepted. Deferred: crawler fetches (separate client), `cache clear` command.

## 2026-08-02: RSS/Atom feeds — and an XML entity bug in three parsers
**Context:** A feed URL passed through as raw XML. Adding a feed parser surfaced a latent defect: **quick-xml 0.39 emits entity references (`&lt;`, `&amp;`, `&#233;`) as their own `Event::GeneralRef`, separate from `Event::Text`.** Every XML walker here handled only `Text`, so escaped characters vanished silently — an Atom `<content>` of escaped HTML arrived as `pThe Rust team.../p` (angle brackets gone), and `R&D` became `RD` in PowerPoint slides. A second trap compounded it: `trim_text(true)` trims *each* text event, and entity refs split a run into several, so the spaces around them were eaten too ("Tom &amp; Jerry" → "Tom &Jerry").
**Decision:** One shared `parsers::resolve_xml_entity` (numeric char refs + predefined entities) wired into feed, powerpoint, and opendocument; `trim_text(false)` in the walkers that accumulate text, trimming at field boundaries instead. Regression tests in all three. New `parsers/feed.rs` handles RSS 2.0 / Atom / RDF with one walker (`item`/`entry`, `description`/`summary`, `pubDate`/`updated`; Atom `href` links preferring rel=alternate, never rel=self); entry bodies (usually CDATA or escaped HTML) go through the DOM extractor like email bodies. `Format::Feed` detects `.rss`/`.atom` plus root-element sniffing, so saved and extension-less feeds work; fetched URLs route by declared type or sniff, falling back to text passthrough if parsing finds nothing. `--full` prefers full `content:encoded` over `summary`. Verified live against Hacker News (RSS) and the Rust blog (Atom).
**Status:** Accepted.

## 2026-08-02: Subtitles (.srt/.vtt) + shared transcript rendering
**Context:** Subtitle files are the clean, ToS-free way to get "the text of a video" (see the YouTube decision above) — and they were falling through to the plaintext reader, emitting cue indices and timing arrows as content. They should also look *identical* to a whisper transcript of the same media: where the timings came from shouldn't change the shape of the markdown.

## 2026-08-02: Pre-publish audit — release config, MCP hardening, real SSRF guard

**Context:** A fresh-eyes audit ahead of the first public release read the whole
tree without deference to this file. It found problems in three classes: a
release that could not be built, an MCP server a real client could kill, and a
set of "fail loudly" violations that contradicted the contract recorded in the
2026-07-27 entry.

**Decision:**

*Release configuration.* `[workspace.metadata.dist] all-features = true`
activated `transcribe-metal`, and whisper-rs-sys defines `GGML_METAL=ON`
unconditionally — only the Apple *framework* link lines are target-gated — so
all three non-Apple targets would have failed at cmake configure. Dist now names
its features explicitly (`web, ocr, wasm, rag, transcribe`), and `transcribe-metal`
is documented as a macOS-only source build. Note the 2026-07-13 entry already
recorded `all-features` breaking once; this was that regression returning, which
is the argument for CI covering the feature matrix rather than the default set
alone. `horde-check.yml` now runs three OSes, the optional engines, and the exact
dist feature list.

*MCP.* `convert`'s `source` argument is model-supplied and was spliced into argv
for `Cli::parse_from`, so a value of `--help` printed clap's output to **stdout**
— corrupting the JSON-RPC stream — and then `exit(0)` mid-request, while `-`
made the server read its own protocol stdin to EOF. Sources are now validated,
passed after `--`, and parsed with `try_parse_from`. Also: invalid UTF-8 on stdin
killed the session rather than yielding -32700; the server replied to JSON-RPC
*responses*; and `2025-03-26` was advertised though that revision made batching
mandatory and we reject batches.

*The MCP pipeline gap.* `gobble_to_string` took `&Cli` and ran none of the
curation/privacy/compression stages, so `--scrub` over MCP returned unredacted
PII with no error — in the one path whose caller is a model rather than a human
who might notice. It now runs the same stages as `gobble_app`.

*SSRF.* `is_blocked_host` had exactly one non-test caller: the redirect policy.
The initial URL was never checked, so `convert` on `http://169.254.169.254/…`
reached the cloud metadata endpoint, and the textual check was bypassable by any
public name resolving to a private address (`localtest.me`, `*.nip.io`).
`net::guard_url` now runs on every fetch — single URL, crawler seed, every crawl
hop, and every redirect — and resolves the host before allowing it. Loopback is
refused by default with `FILEGOBLIN_ALLOW_LOCAL_URLS` as the opt-in. The
resolve-then-connect TOCTOU that remains is documented in the function rather
than papered over; closing it needs a resolver hook in the HTTP client.
The comment claiming `--browser`'s initial host "was already validated by the
reqwest fetch above" was simply false and has been corrected.

*Silent data corruption.* Two cases produced *wrong* output rather than missing
output, which is worse: OpenDocument dropped self-closing `<table:table-cell/>`
— what LibreOffice writes for every blank cell — so every value to its right
moved one column left; and the feed walker cleared its buffer on every `Start`,
so an Atom `<content type="xhtml">` with nested elements produced an entry with
no body at all. Table rendering existed in five copies with a different bug in
each; docx/pptx/ODF now share one `TableBuilder` that pads rows to a single
width.

*Two reachable panics*, both on ordinary input: `feed.rs` sliced fetched text at
byte 1024 and `pdf.rs` sliced OCR output at byte 40, neither on a char boundary,
so any non-English page fetched by URL or any CJK scanned PDF aborted the
process. Both now go through `parsers::str_prefix`.

*Zip-bomb coverage.* The cap in `archive.rs` is well built — it counts actually
decompressed bytes rather than trusting the declared size — but it was the only
place that inflated attacker-controlled data. `.docx`/`.pptx`/`.odt`/`.epub` are
zip containers too and read members with `read_to_string`; they now share a
capped reader.

**Status:** Accepted. The TUI is parked (excluded from the workspace, dropped
from the CLI manifest, `--interactive` removed) rather than fixed: it shipped a
v1.5 banner against a 1.11 workspace, its URL browsing was dead in every binary
because the `tui` feature never propagated `filegoblin-tui/web`, and it
hex-dumped the formats the README advertises. Re-integration notes are in its
Cargo.toml. Deferred: `--browser` inside `--horde` (still unwired, now with a
runtime note), DNS-rebinding protection, and a resolver-level SSRF hook.

## 2026-08-02: Audit follow-through — the deeper items

**Context:** After the pre-publish batch above, the remaining audit findings
were the ones that needed real work rather than a targeted fix: duplicated
output framing, quadratic HTML scoring, an untested crawler, and a set of
smaller correctness bugs.

**Decision:**

*One output framing.* `FILE_START` had five implementations across
`formatters.rs` and `lib.rs`, differing in trailing newlines and in whether they
carried the relevance score, so a format change had to be made in five places
and a miss would surface as two output modes disagreeing. Now one
`formatters::render_block`. Golden snapshots are byte-identical across the
change, which is the evidence it was a pure refactor.

*HTML scoring is one pass.* Content selection and link-farm removal each
measured every candidate independently, and since every ancestor `div` contains
its descendants' text, the work multiplied out on nested markup — a 35 KB page
of 3000 nested divs took 4.29s, and 3.5s of that was ours. Both now read from a
single bottom-up O(nodes) accumulation (`accumulate_text_sizes`), bringing it to
0.66s.
Honest finding: that did **not** make it linear. Timing `--full`, which skips
both functions, shows the same ~4×-for-2× curve, so the residual is inside
html5ever/html2md. Rather than claim the problem solved, documents nesting past
1000 levels are refused outright — real pages nest a few dozen, and `--horde`
fetches from arbitrary sites, so an unbounded parse is a genuine DoS vector.

*Crawler scoping, now tested.* The page budget compared `MAX_PAGES` against
`visited`, which counts *discovered* URLs, so one page linking to 600 others
exhausted the crawl before a second page was fetched. The same-origin check
compared `host_str()` alone, so a crawl of a web site would follow links to
other services on the same host (`:8443`, `:22`). Scoping is extracted into
`normalize_link` and covered by the crawler's first tests.

*Spreadsheets say what the sheet says.* `Data::Float` printed the stored binary
value (`0.30000000000000004` for a cell showing `0.3`) and `Data::DateTime`
printed its serial number (`45292.5`). Floats round to the 15 significant digits
Excel itself guarantees; serials convert to `YYYY-MM-DD [HH:MM:SS]` by hand
rather than adding chrono, since calamine only exposes that behind a feature.
Excel's phantom 1900-02-29 is handled.

*Scrubbing keeps its context.* The generic assignment rule matched the key name
along with the value, so `api_key = sk_live_…` became a bare `[SECRET]` and the
line lost the one thing that said what was removed. The name and separator are
preserved now.

*Nested structures stopped corrupting their hosts.* A table inside a docx cell
was rendered as a pipe table and then newline-flattened by the parent into
`| a | b |---|---| c |`; it flattens to readable text instead. An ODF footnote
nests a whole `text:p` inside the citing paragraph, and treating that inner
close as the paragraph's end split the sentence and spliced the note into the
remainder; paragraph depth is tracked and note bodies are emitted after the
paragraph.

**Status:** Accepted. Still open and deliberately so: the html5ever/html2md
nesting cost (mitigated by the depth cap, not fixed); MCP is still sequential
with no cancellation, so a slow conversion blocks `ping`; DNS rebinding remains
possible between `guard_url`'s resolution and the connection.

## 2026-08-02: Closing two of the three deferred items

**Context:** The follow-through entry above left three things open. Two turned
out to be worth doing properly rather than living with.

**DNS rebinding — closed, by moving the check into the resolver.** `guard_url`
resolved a host to *validate* it and reqwest then resolved independently to
*connect*, so a record that changed in between — or a round-robin answering
public once and private next — slipped through. A `reqwest::dns::Resolve`
implementation (`net::GuardedResolver`, wired into both the blocking and async
clients) now filters at resolution time, which makes the answer that gets
validated the same answer that gets connected to. A name resolving to a mix of
public and private addresses is refused outright rather than connecting to the
public one, since a mixed answer is the signature of a rebinding attempt.
`guard_url` stays as the early, friendly check that can explain itself before a
connection is attempted; the resolver is the authoritative one. Tested by
driving the client directly at a loopback name, bypassing `guard_url` entirely,
and asserting the refusal comes from the resolver (walking the error's source
chain — reqwest's Display is only "error sending request").

**MCP head-of-line blocking — closed for the case that mattered.** The read
loop was strictly sequential, so a large PDF or repository conversion blocked
`ping`, and a client that pings on a timer concludes the server has died.
`tools/call` is the only method slow enough to matter, so only it moves to a
worker thread (capped at 4 in flight, degrading to inline beyond that);
everything else is still answered inline, which keeps handshake ordering
untouched. Responses are written under one stdout mutex so two workers cannot
interleave halves of a line into the protocol stream. `notifications/cancelled`
is now acted on rather than merely tolerated: the id is recorded and a worker
that finishes afterwards drops its response, per the spec's requirement that a
cancelled request MUST NOT be answered. What is *not* implemented is preemption
— a running conversion still runs to completion in the background; cancelling
frees the client, not the CPU.

**html5ever/html2md nesting cost — deliberately left.** The 1000-level depth cap
already bounds the DoS, and going further means patching or replacing a
dependency to serve input no real document produces. Poor return; revisit only
if a real page ever trips the cap.

**Status:** Accepted.

## 2026-08-03: `--walk` — browse and pick, instead of swallowing a whole site

**Context:** `--horde` on a website converts everything reachable, so a docs
site hands back its changelog, blog archive and language variants alongside the
four pages that were wanted. You cannot tell what is worth converting until you
have seen it, and by then it is all converted. The parked TUI had solved this —
browse, preview, select — and losing it removed the only way to do so.

Investigation turned up a second, worse problem: **`--depth` and
`--include`/`--exclude` are applied by the local file walker and never read by
the crawler**, so `--horde --depth 1` against a URL silently crawled the whole
site. There was no working way to scope a web crawl at all.

**Decision:** Two modes, with the existing behaviour unchanged as the default.
`--walk` opens an interactive picker; everything else works exactly as before.
Interactive is opt-in and requires a TTY, because agents, pipes and the MCP
server all call this binary and a default that waits for a keypress would break
all three.

Split along the lib/bin line the project already keeps: `core::explore` is the
headless engine — *what does this node render as, and where does it lead* — for
both sources (a URL previews as its converted page and leads to same-origin
links; a directory previews as a listing and leads to its entries; a file
previews as its conversion and leads nowhere). `cli::walk` is the screen. That
keeps the interesting edge cases (link scoping, dedup, dotfiles, unconvertible
nodes) in library tests, and navigation state (`WalkState`) is pure so every
keypress is a testable transition rather than something only reachable through a
terminal.

Reuse rather than reimplementation is what made this small: previews go through
`gobble_to_string`, so the preview *is* the output, with scrubbing and
compression applied; link scoping calls the crawler's `normalize_link`, so
walking and crawling agree on what counts as "this site" (including the port);
and the URL cache makes backing up free. Selection ends by handing targets to
the same `gobble_app` every other path uses, so output modes, exit codes and
redaction need no special cases.

crossterm for keys, drawing hand-rolled: the layout is one static screen, and
ratatui would be a large dependency for it — that was the parked TUI's weight,
and re-adding it to solve a smaller problem would be a poor trade. The UI draws
to **stderr**, preserving the stdout-is-sacred invariant, so
`filegoblin --walk <target> > out.md` behaves like every other invocation.

Verified by driving the real binary in a PTY for both sources: a directory walk
(selection surviving navigation in and out of subdirectories, and a selected
directory correctly pulling in everything beneath it) and a served local site
(following a link, converting the new page, finding *its* outbound links, and
excluding the offsite one). In both cases the unselected "junk" page stayed out
of the output and stdout carried only markdown.

**Status:** Accepted. Still open: `--depth` and `--include`/`--exclude` remain
unwired for crawls — `--walk` sidesteps that rather than fixing it, and the
cheap non-interactive scoping is still missing. Also deferred: search/filter
within the picker, and multi-select across a whole subtree at once.

## 2026-08-03: Crawl scoping — wiring up flags that were silently ignored

**Context:** `--depth`, `--include` and `--exclude` were applied by the local
file walker and never read by the crawler, so `--horde --depth 1` against a URL
crawled the entire site. Every documented way to scope a crawl was a no-op, and
`--walk` (added just before this) routed around the problem rather than fixing
it — which left scripts, agents and the MCP server with nothing.

**Decision:** One `CrawlScope`, built once from the args, consulted when a link
is discovered. Two choices worth recording:

*Prune the frontier, not the output.* An out-of-scope page is never fetched, so
scoping saves requests and time instead of downloading everything and printing
less. The alternative — traverse everything, filter what is kept — would leave
`--include "/guide/*"` still crawling the whole site, which is the opposite of
the point. The cost is that a wanted page reachable only *through* an excluded
one becomes unreachable; that is the right default for a tool whose failure mode
is grabbing too much, and `--walk` covers the case where you need to see the
route.

*Patterns match the URL path, reusing the existing glob flags* rather than
adding `--url-include`/`--url-exclude`. `--horde` already means "local or web",
so its filters should too. globset's default (`literal_separator = false`) makes
`*` cross `/`, so the bare-word shorthand — `--include guide` becoming
`*guide*` — matches `/docs/guide/start.html` as a user would expect; there is a
test pinning that, because the opposite default would silently match nothing.

The seed is always fetched regardless of `--include`, or scoping a crawl to a
subsection from the site root would match nothing and crawl nothing.

Verified against a served local site: unscoped reaches 5 pages; `--depth 1`
fetches 4 and excludes the depth-2 page; `--depth 2` reaches it again;
`--exclude blog` and `--include guide` each drop the right page.

**Also in this pass:** `html_attr` recognised only `name="…"` and returned the
value raw, so single-quoted attributes were invisible and `?a=1&amp;b=2` kept
its entity. PDF scanned-page OCR read only the *largest* embedded image, so a
book spread scanned as two halves silently lost one — it now reads every image
within an eighth of the largest, capped at 8 per page since OCR is the slowest
thing here.

**Status:** Accepted.

## 2026-08-03: Removing the TUI crate

**Context:** The TUI was parked (excluded from the workspace, dropped from the
CLI) rather than deleted, on the theory that its browse-and-select workflow was
worth re-integrating once its staleness was fixed. `--walk` has since been built,
which makes that theory obsolete.

**Decision:** Delete it. `--walk` covers the purpose — exploring deeply nested
directories and sites — and covers it better on every axis that mattered:

| | parked TUI | `--walk` |
|---|---|---|
| preview | raw bytes (a PDF rendered as a hex dump) | the actual converted markdown |
| web links | present but **dead in every shipped binary** (the `tui` feature never propagated `filegoblin-tui/web`) | follows them, same-origin scoped |
| formats | list stale at ~v1.5 | whatever the router supports |
| tests | zero, across 1085 lines | 9 state + 5 engine |

The one capability that does not carry over is toggling `copy`/`open`/`scrub`/

reproducibility than typing them — a run you can't reconstruct from its command
is a run you can't script.

Keeping it parked had an ongoing cost: outside the workspace, nothing built it
during normal development, so it could only rot, and it needed a dedicated CI

## 2026-10-10: Deterministic PDF Layout Ordering, Header/Footer Suppression, and Table Boundary Spacing

**Context:** Real-world PDF conversion for complex documents (two-column layouts, tables, sidebars, and running headers/footers) exhibited three critical failure modes:
1. *Running Header/Footer Leakage:* Page numbers (isolated folios), running chapter/journal headers, and printer production slugs were injected between paragraphs across page boundaries, interrupting sentences and degrading downstream LLM context.
2. *Multi-Column Reading Order & Line Interleaving:* In scanned and Vision-OCR documents, recognized spans across adjacent columns or consecutive vertical lines were sorted solely by vertical position and clustered within a loose scalar band (`Y_BAND = 0.015`). Because typical text line height and spacing are both ~0.014, consecutive vertical lines were pairwise merged and horizontally scrambled. Soft hyphens across line breaks were also left broken.
3. *Table & Block Boundary Mangling:* Extracted markdown tables and callouts lacked guaranteed empty line boundary separation, causing CommonMark/GFM parsers to swallow or distort following paragraphs. Column count mismatches between headers and separator rows also corrupted pipe tables.

**Decision:**
- **Header/Footer Suppression (`crates/core/src/parsers/pdf.rs`):** Implemented `filter_running_headers_and_footers` using two-pass boundary analysis. Explicitly protects Page 0 document titles and author blocks (`is_document_title_block`).
- **Geometric Reading Order & Line Assembly (`crates/core/src/parsers/ocr.rs`):** Introduced `OcrBox` geometry struct. Implemented deterministic two-column gutter detection (`detect_two_column_gutter`) to find vertical separator corridors $x \in [0.35, 0.65]$ and band-based page partitioning (`partition_two_column_page`) to preserve full-width title banners before sequencing column 1 top-to-bottom, then column 2 top-to-bottom. Line assembly (`assemble_lines_within_group`) now requires vertical overlap ($\ge 40\%$ min height) and strictly prohibits horizontal overlap ($\le 15\%$ min width), preventing consecutive lines from ever collapsing. Added automated soft-hyphen dehyphenation (`join_lines_with_dehyphenation`).
- **Table & Block Boundary Spacing (`crates/core/src/parsers/pdf.rs`):** Implemented `format_table_and_block_boundaries` to guarantee empty line padding before and after tables and blockquotes, synchronize separator row column widths to match header rows, protect code fences, and collapse redundant newlines.
- **Zero Hallucination Standard:** Complex raster diagram topologies and display equations are retained as extracted OCR text (`> **Text from embedded image:**`) without guessing or hallucinating synthetic graph structures or ungrounded LaTeX.

2. *Patent & Legal Line-Number Gutter Interleaving (`PATENT_1`):* Periodic line numbers in USPTO patent gutters (5, 10, 15, 20...) interleaved into body text across columns (`limita 5 tions` -> `limitations`, `also be 10 implemented`). In addition, patent claims were mistakenly wrapped in fenced Markdown code blocks due to paragraph indentation.
3. *Full-Width Header & Banner Bisection (`FDA_1`):* Top banners spanning across the page were bisected by column partitioning into fragmented words (`HIGHLIGHTS OF PRESCRI` and `BING INFORMATION`), exacerbated by clamped top cut-offs dropping metadata on initial pages.

**Decision:**
1. **Header Deduplication Length Ratio Gate (`headers_match` in `crates/core/src/parsers/pdf.rs`):**
   - Enforced a minimum relative length ratio `(min_len as f64) >= (max_len as f64) * 0.6` before substring containment triggers deduplication.
   - Prevents substantive opinion transition sentences from being swallowed by short running header phrases.
2. **Geometric Gutter Line-Number Detection & Column Contraction (`detect_vertical_line_numbers` & `convert_page_text` in `pdf.rs`):**
   - Implemented geometric cluster analysis detecting vertical columns containing monotonic multiples of 5 (5..70) with bounding box widths <= 20.0 pt and regular vertical step deltas (15..=120 pt).
   - Dynamically contracts left and right column boundaries away from the central gutter corridor (`left_col_w = g_min - 1.5`, `right_col_x = g_max + 1.5`), isolating gutter numbers from text capture.
   - Supplemented with periodic integer stripping between words (`LINE_NUM_BETWEEN_WORDS_RE`) and at line boundaries (`LINE_NUM_AT_LINE_END_RE`).
3. **Generic Derivational Morphology Line-Wrap Healing (`SUFFIX_LINE_WRAP_RE` & `PREFIX_LINE_WRAP_RE` in `pdf.rs`):**
   - Added linguistic morphology healing to reunite Latin and Greek derivational suffixes (`-tions`, `-tion`, `-mentation`, `-ment`, `-fication`, `-fied`, `-versely`, `-ingly`, etc.) separated from vowel stems across line wraps (`limita  tions` -> `limitations`).
   - Purely algorithmic and vocabulary-driven, adhering strictly to the Generalization Firewall.
4. **Patent Claim & Legal Prose Code Block Unwrapping (`unwrap_false_prose_code_blocks` in `pdf.rs`):**
   - Detects language-less fenced code blocks containing patent claim syntax (`"What is claimed is"`, `"The system of claim"`, `"comprising:"`, `"wherein the"`) without programming language syntax (`{`, `}`, `fn`, `def`, `class`, `pub struct`), restoring them to natural markdown prose.
5. **Full-Width Top-Band Height Bounding (`convert_page_text` in `pdf.rs`):**
   - When a page lacks a spanning top band, `top_cut` is assigned directly to `height` instead of a clamped offset, ensuring two-column bounding boxes capture top-of-page patent numbers, titles, and filing metadata.
   - For single-column pages and spanning top bands, `ReadingOrderMode::TopToBottomLeftToRight` is preserved to keep wide banners (`HIGHLIGHTS OF PRESCRIBING INFORMATION`) contiguous.
6. **Harness Word-Boundary Discrimination (`scripts/run_gauntlet.py`):**
   - Enforced regex word boundaries `(?<![A-Za-z0-9])` ... `(?![A-Za-z0-9])` in `forbidden_absent` checks to prevent healed whole words from triggering false-positive fragment failures.

**Verification & Outcomes:**
- **Adversarial Enterprise Gauntlet:** **29/29 (100.0%) PASS** with exit code 0.
- **Fidelity Benchmark:** Zero header/footer leaks, zero sentence interruptions across all full books and slices. Slice E (Zeitz Math) maintained **85.3% Recall** and **85.8% Precision** ($\ge 85.0\%$). Attention Is All You Need valid tables: **6/6 (100.0%)**.
- **Rust Engine Quality:** 232 workspace unit/integration tests passing cleanly; 0 clippy warnings; formatting clean.

**Status:** Accepted.

## 2026-10-11: Phase 7 Multi-Format Output Engine (--format markdown|plain|json) and Layout-Aware Semantic Chunking

**Context:**
Downstream RAG (Retrieval-Augmented Generation), vector embedding models (e.g. OpenAI `text-embedding-3`, Cohere, BGE), and LLM agent pipelines have distinct structural requirements:
1. Dense vector embeddings and BM25 search engines require clean plain text stripped of Markdown syntax tokens (headings `#`, math delimiters `$`, markdown link syntax `[text](url)`), but require tables formatted with space-padded columns to preserve tabular association.
2. Large documents exceeding context windows require chunking that respects document layout structure rather than blindly cutting across sentences, code blocks, or data tables.
3. When multi-row tables are split across chunk boundaries, isolated continuation rows lack header semantics, confusing retrieval embeddings and LLMs.
4. Chunks without hierarchical context (e.g., Section > Subsection) lose parent thematic awareness.

**Decision:**
1. **Unified Output Format (`--format <FORMAT>` / `-f`):**
   - Added `OutputFormat` enum: `Markdown` (default), `Plain`, and `Json`.
   - Maintained full backwards compatibility with legacy `--json`.
   - `plain` formatter (`crates/core/src/formatters/plain.rs`):
     - Strips heading `#` prefixes while preserving heading text.
     - Strips link markdown `[text](url)` to plain anchor text `text`.
     - Strips inline (`$ ... $`) and display (`$$ ... $$`) LaTeX math delimiters while keeping equations.
     - Formats Markdown pipe tables into space-aligned columnar text.
     - Unwraps fenced code blocks while preserving code content.
     - Preserves `<!-- Context: ... -->` outline breadcrumbs.
2. **Layout-Aware Semantic Chunking Engine (`crates/core/src/chunking/mod.rs`):**
   - CLI flags: `--chunk-size <TOKENS>` (supports bare numbers or `1k`, `2m`), `--chunk-overlap <TOKENS>` (default: 50), `--chunk-strategy <layout|tokens>` (default: `layout`).
   - `OutlineTracker`: Tracks document heading depth (H1 > H2 > H3), prepending `<!-- Context: Section > Subsection -->` in markdown/plain or populating `"breadcrumbs": [...]` in JSON.
   - `parse_semantic_blocks`: Deconstructs markdown into semantic units (`Heading`, `CodeBlock`, `Table`, `ThematicBreak`, `Narrative`).
   - `chunk_document_layout`:
     - Splits strictly along semantic structural boundaries (H1, H2, or when level <= previous heading level).
     - Protects code blocks and short tables from being cut in half.
     - **Table Context Preservation:** When large tables exceed `--chunk-size`, the table header and separator rows are automatically replicated at the start of every continuation chunk.
     - Seeds narrative continuation chunks with `--chunk-overlap` tokens from preceding narrative blocks.
   - `chunk_document_tokens`: Fallback hard sliding-window tokenizer chunker.
3. **Structured JSON Output Schema:**
   - When `--format json` is combined with `--chunk-size`, emits an array of chunk objects:
     `[{"file": "...", "chunk_index": 0, "total_chunks": N, "breadcrumbs": [...], "content": "...", "tokens": T}]`.
   - Single unchunked files with `--format json` continue emitting `{ "path": "...", "format": "...", "tokens": T, "content": "..." }`.

**Verification & Outcomes:**
- **Adversarial Gauntlet:** 29/29 (100.0%) PASS with exit code 0.
- **Fidelity Benchmarks:** Zero header/footer leaks, zero sentence interruptions, Slice E (Zeitz Math) $\ge 85.0\%$ recall & precision, Attention Is All You Need 6/6 valid tables.
- **Unit & Integration Tests:** 5 end-to-end integration tests in `crates/cli/tests/format_and_chunking.rs` verifying plain markdown stripping, JSON schema compliance, table header replication across chunk boundaries, and outline breadcrumb hierarchy.
- **Workspace Health:** 240 unit/integration tests and 21 golden tests passing with 0 warnings on clippy and clean rustfmt.

**Status:** Accepted.



## 2026-10-11: PDF engine de-overfitting — geometric furniture, no prose rewriting

**Context:**
The audit (`docs/agent_context/AUDIT_REPORT.md`) found that the 29/29 gauntlet result had been reached partly by hard-coding the benchmark: verbatim sentences from *Attention Is All You Need* with hand-written LaTeX answers, 46 literal word fixes from the Zeitz scan, a *Thinking in Systems* sentence, and global regex passes that "healed" one document's defects everywhere. Those passes corrupted ordinary text in every PDF: drug doses in the Keytruda label ("KEYTRUDA 200 mg" → "KEYTRUDA200 mg", "axitinib 5 mg" → "axitinibmg"), legal citations ("64, 78 (1938)" → "78), (1938)"), form references and code identifiers. A text-level running-header filter deleted real headings ("Section 3: …") that recurred with different numbers. Separately, `include_artifacts: false` switched on `pdf_oxide`'s own untagged-header heuristic, which drops any top-band line whose digit-stripped text repeats — the same heading bug, upstream.

**Decision:**
1. **Delete every document-specific literal and every word-level regex pass** from `pdf.rs` (Attention/Zeitz/Meadows literals, the 46-replace chain, line-number regexes, suffix/prefix healing, `COORD_DIGIT_OPEN_PAREN_RE`, `SECTION_NUM_RE`, `CAMEL_PROSE_RE`, the OCR-math regexes, callout disentangling, the author zipper, keyword title promotion, publisher-slug keywords, the dead CMSY table). Post-conversion passes may now only change structure (block spacing, false headings, page joins), never the words of prose. A unit test (`prose_is_never_rewritten`) pins this.
2. **Furniture is decided geometrically, before conversion** (new `parsers/pdf_furniture.rs`), and excluded via `ConversionOptions::exclude_regions`:
   - running headers/footers: outermost rows in a band near the page edge, recurring (numbers masked) on ≥ 20% of pages or in a run of nearby pages, at a consistent distance from the edge, and set no larger than body text — a heading-sized line is never furniture;
   - folios: lone page numbers whose value advances with the page index (a cover-page "2023" does not);
   - line-number gutters: isolated integers in an empty vertical channel, increasing by a constant step at a constant pitch, standing in a margin or between two columns. Because exclusion works on whole spans, gutter numbers merged into a span are also removed from the text — once, and only between the neighbouring words they had on the page.
   OCR'd pages (no geometry) use the same recurrence/folio rules on their first and last lines.
3. **`include_artifacts: true`**: `pdf_oxide`'s untagged-header heuristic is not used.
4. **Word repair from evidence, not word lists**: line-break hyphenation is joined only for pairs geometry recorded as a line-end hyphen, with the document's own vocabulary deciding compound vs syllable break; words split by a dropped hyphen are rejoined on geometric or vocabulary evidence; tokens the converter ran together are split only where the page shows a word gap *and* the characters show a boundary (case change, letter↔digit, punctuation); letter-spaced headings are rejoined from measured gaps.
5. **Recovered tables must have real columns**: interior column boundaries must be ruled or clearly wider than the page's word spacing.
6. **Two-column band detection** now uses the real page box (origin, size) and scales its scan with the body font size instead of US-Letter point constants.
7. **New evaluation** (`scripts/pdf_eval.py`) beside the gauntlet: synthetic survival PDFs with exact ground truth (`test_assets/pdf_survival/`, generator `scripts/gen_pdf_survival.py`), verbatim must-survive phrases from real documents (doses, citations, form lines), and fidelity against `pdftotext` with a neutral normaliser (word recall/precision, 4-gram recall, numeric survival). `scripts/run_gauntlet.py` now resolves paths from the repo and honours `FILEGOBLIN_BIN`.

**Outcomes** (Linux, debug build with `--features ocr`; same harness for both columns):

| | Before | After |
|---|---|---|
| Gauntlet (all 29) | 29/29 | 28/29 — R2 fails |
| Survival checks (synthetic + real-document phrases) | 37/80 | 78/80 |
| Fidelity vs pdftotext, mean of 26 PDFs: recall / precision / 4-gram / numeric | 91.1 / 89.0 / 76.0 / 71.6 | 95.9 / 91.0 / 84.5 / 91.8 |
| Held-out memo: section headings kept | 2/6 | 6/6 |
| Keytruda dose phrases intact | 1/4 | 4/4 |

R2's canary is `\le`, but the Zeitz page's text layer contains the OCR misreading `::;` and no ≤ anywhere; the only way to produce `\le` is to rewrite that specific misreading, which is the practice this entry removes. The canary should be replaced with a phrase the page actually contains. The two remaining survival misses are compounds broken at a line-end hyphen in a 10-line document ("well-known", "Self-supervised"): with no other occurrences to learn from, the vocabulary rule defaults to joining. Not verified on macOS (Apple Vision OCR path).

**Status:** Accepted.

## 2026-10-11: PDF pass speed-up and table compaction

**Context:** Profiling the PDF pipeline showed most time inside `pdf_oxide` re-reading pages: classification, geometry and conversion each parsed every page again, because its parsed-page cache holds only eight pages and the stages ran as separate passes over the whole document. Table detection also ran on every page just to rule out a two-column split.

**Decision:**
- Classify and collect geometry for a page in the same task, so geometry reuses the classification's parsed page (extract_words dropped from 2.6 s to 0.4 s of CPU on the Keytruda label).
- Check for tables only after a two-column band has been found, and detect tables for the line-number guard only on pages with a gutter candidate.
- Emit PDF tables with empty rows and empty columns removed and cell padding normalised (same `| a | b |` dialect as every other parser), and collapse runs of spaces in prose.

**Outcome:** gauntlet PDFs convert 19% faster (21.6 s → 17.5 s for the 16 gauntlet PDFs on 2 cores) with no words changed (only whitespace and empty table cells differ); all quality metrics unchanged (survival 78/80, gauntlet 28/29, pdftotext fidelity identical); output 1.9% smaller in GPT-4o tokens. A compact table dialect (`|a|b|`, `|-|`) would save roughly 3% more but changes every parser's output and two gauntlet syntax canaries, so it is left as a separate decision.

**Status:** Accepted.

## 2026-10-12: PDF vision pipeline — bundled layout, formula, table and OCR models

**Context:** After the de-overfitting work the PDF engine was honest but limited by what a text layer can say. On an external benchmark (olmOCR-bench: 1,403 single pages, 7,010 machine-checkable tests across arXiv math, scanned math, tables, old scans, headers/footers, multi-column and tiny text), the geometric engine scored 33.2% on the full set, below the pre-refactor engine (35.1%, whose keyword heuristics happened to remove more single-page headers) and only a little above `pdftotext` (30.5%). It scored 0% on both math categories, because no text layer contains LaTeX. It was weak on tables, reading order and scans for the same reason. The user asked for the best possible output with three constraints: everything bundled, cross-platform, and no outside software or LLMs at runtime. Size and speed are secondary.

**Decision:** Add an opt-in `vision` feature. Under it, PDFs are rendered and read by bundled ONNX models running on `rten` (pure Rust, already a dependency through `ocrs`):

| Stage | Model | License |
|---|---|---|
| Rendering | `hayro` 0.7 (pure-Rust rasterizer, embedded standard fonts). `pdf_oxide`'s renderer was rejected: wrong fonts, no clipping | MIT/Apache-2.0 |
| Layout + reading order | PP-DocLayoutV3. 25 region classes, including inline formulas and page furniture, plus a pairwise reading-order head | Apache-2.0 |
| Formula → LaTeX | pix2text MFR 1.5 (DeiT encoder + TrOCR decoder). The decoder is rebuilt with a KV cache from the released weights and checked to 1e-3 in logits against the original | MIT |
| Table structure | Table Transformer v1.1 "all" | MIT |
| OCR | PP-OCRv5 mobile detection + English recognition, from PaddlePaddle's official ONNX exports | Apache-2.0 |

AGPL-licensed weights (YOLO-based formula detectors, MinerU's) were excluded on purpose.

Rules of the assembly (`parsers/pdf_vision.rs`):
- **The model never invents words on text-layer pages.** Words come from the PDF. The layout model only decides which region each word belongs to (smallest region containing its centre), in what order regions are read, and which words are furniture. Furniture regions count only near the top or bottom edge. Text inside figures and charts is dropped.
- **Words no region claims are never dropped.** They are grouped into blocks and placed after the nearest region above them in the same column.
- **Formulas are the exception.** They are re-read from the image because a text layer cannot express them. Display formulas become `$$…$$`. Inline formulas replace the words under them with `$…$`; sentence punctuation the detector included moves back outside. A formula split by a line break after an operator is rejoined. Recognizer output is canonicalised (spacing commands dropped, `\operatorname{log}` → `\log`, emphasis wrappers on heavy print removed). A display formula keeps the sentence punctuation it carries.
- **Tables:** the model gives rows, columns, header rows and spanning cells; the text layer fills the cells; a spanning cell's text repeats in each cell it covers. Output stays in the one pipe-table dialect.
- **Scans, and text regions the text layer leaves empty, go through OCR.** Lines are detected as rotated boxes and warped upright before recognition, so skewed book pages read correctly. This also covers pages the classifier calls empty but that render (JBIG2 masks).
- **Cleaning up after the layout:** paragraphs cut by a column or region break are rejoined when the first block stops mid-sentence and the next starts lowercase. Tokens set flush in the text layer stay joined. Ligature code points are spelled out. Dehyphenation no longer counts a word's own line-break fragments as vocabulary evidence; this fix also applies to the non-vision path.
- **Model loading:** all models load eagerly on the calling thread. Lazy loading inside the page-parallel loop deadlocked: rten's load-time optimizer waits on a pool, and a rayon worker steals another page job that waits on the same `OnceLock`.
- **Model files:** weights are found in `$FILEGOBLIN_MODELS`, `models/` next to the binary, or `~/.filegoblin/models`. `bundled-models` compiles them in (~370 MB). `scripts/vision_models.py` rebuilds every file from its upstream source, including the conversions rten needs: an f64-free graph, opset upgrade and Conv epilogue folding. `--vision off` (or `FILEGOBLIN_VISION=0`) turns the pipeline off; `--vision smart` (default) routes per page from text-layer facts (no text layer, math fonts/symbols, column-aligned tables, multi-column, pictures, ≤2-page documents) and keeps plain prose on the fast path; `--vision all` sends every page through the models. Release builds include the runtime; the weights ship as a separate `filegoblin-vision-models.tar.gz` asset, and without them filegoblin behaves like the fast converter.

**Outcomes:** full olmOCR-bench (1,403 PDFs, 8,413 tests incl. baseline), official scorer, mean of per-file scores:

## 2026-10-14: Headings, EDGAR furniture, layout tables, deterministic scans

**Context:** after the graded gauntlet landed, its weakest components were headings (0 on most SEC and legal filings), page furniture leaking from HTML and PDFs, prose written as pipe tables, and one remaining smart-mode failure (PATENT_1). Chasing an unexplained score dip on R2 also turned up nondeterministic output on scanned PDFs.

**Decision:**
- **Thread safety.** Two pdf_oxide calls, page classification and image extraction, are serialized behind locks. Under parallel calls, a scanned page could be classified or OCR'd from the next page's images. Text shifted by one page, or a page went missing, in 1 run in 4–8 of a 5-page scan. OCR and conversion stay parallel. All 29 cases now give byte-identical output on repeated runs.
- **One heading pass for HTML and PDF** (`parsers/headings.rs`). Two kinds of standalone block become ATX headings, with the level taken from the numbering:
  - a short bold span;
  - a numbered title, such as `1.1 …`, `Section 2.14 …`, `Item 1A. …`, `Table 4-1. …` or `1.01 SECTION INCLUDES:`.

  A bold all-caps run-in lead is split off. Sentences, labels, values, tables, lists and code are never promoted.
- **HTML pre-pass** (`parsers/html_prep.rs`).
  - *Before content extraction:* the EDGAR SGML wrapper and `display:none` elements are removed. Furniture at page breaks is found by recurrence and removed: an exact match at 20% or more of breaks, or a match after normalizing digits at 50% or more, or a bare page number.
  - *After extraction, per fragment:* layout tables (one row of text, or rows of marker plus text) become paragraphs. Short blocks set 15% or more larger than the body text become h2–h4. CSS bold becomes `<b>`, and `<sup>` footnote marks become `[^n]`.
  - Unwrapping layout tables *before* extraction made the extractor stop treating EDGAR filings as table-heavy and cut them to one block, so that step runs afterwards.
- **PDF.**
  - *Code fences:* a fenced block that stays code is copied whole. Its closing fence used to be read as the next block's opening, which left one fence open to the end of the document. A page can no longer leave a fence open, and documents that are mostly monospace unwrap blocks that have no code syntax.
  - *Glued capitals* are split using the document's own vocabulary.
  - *Hyphens before suffix fragments* ("limita-|tions") are rejoined.
  - *Running heads on pages printed inside a smaller trim* count as furniture when their row carries a page number.

**Result** (M4 Pro, 29 cases):

| | canaries | quality |
|---|---|---|
| `--vision off`, before | 28/29 | 74.9 |
| `--vision off`, after | 28/29 | 82.1 |
| `--vision smart`, before | 28/29 | 81.9 |
| `--vision smart`, after | **29/29** | **87.9** |

Formats are 29/29. The largest gains are on SEC_PROXY (+24), FIN_2 (+18), LEGAL_VIE (+19), SEC_S1 (+16), SEC_CREDIT (+10) and FIN_1 (+9). No case lost more than 0.7.

**Open:**
- Merck's two-column page layouts (sidebar tables) still come out as tables.
- Patent drawing-sheet heads ("Sheet N of 3") sit on rotated pages and are not removed.
- Furniture that appears on only one page leaks, for example a signature-page document ID.
- Table structure without the models (`--vision off`) is weak on papers and annual reports.

**Status:** Accepted.

## 2026-10-15: Scan accuracy — PP-OCRv6, damaged OCR layers, scan furniture

**Context:** the research round on scan accuracy (two external reports, analysed in the project's `research/2026-10-14-scan-accuracy-analysis.md`) pointed at three levers: scans whose own OCR layer is garbage keep that garbage, the bundled recognizer (PP-OCRv5 mobile, English) is weak on degraded print and handwriting, and the assembly of OCR'd pages leaks furniture. Measured on the gauntlet and on olmOCR-bench's two scan categories (official tests, KaTeX math scoring).

**Decision:**
- **PP-OCRv6 medium replaces PP-OCRv5 mobile** (Apache-2.0, PaddlePaddle's official ONNX exports, converted for rten and checked against onnxruntime). The detector and recognizer are picked from what is installed (v6m, then v6s, then v5) with per-model DB thresholds; `FILEGOBLIN_OCR_DET` / `FILEGOBLIN_OCR_REC` override for comparisons. The release bundles v6m only (+~125 MB). About 2–3× slower per scanned page than v5 mobile.
- **Dropped word spaces are restored from CTC timing.** The multilingual v6 recognizers often emit nothing in a space's slot ("couldtell", "borderforfifteen") on English print and typewriter text. A gap of about two symbols between two letters of a spaced script becomes a space; unspaced scripts are left alone.
- **Text-layer quality gate** (`parsers/pdf_textq.rs`). Pages with a scanner's OCR layer — invisible text, a page-sized picture, or Acrobat ClearScan's synthesized `Fd…` fonts — are scored on the fast converter's own words: loose single letters (other than a/A/I), OCR garbage tokens (Taghva-style rules), unmappable characters. A layer that fails (≥4% single letters, ≥8% garbage, or ≥3% unmappable) is re-read from the image by the layout + OCR models; without the models, by the platform OCR engine, but only when one picture covers the page. Clean prose layers are kept.
- **Smart routing** also sends pages whose layer spells formulas as loose letters (≥8% single letters) to the models.
- **Formulas:** LaTeX that KaTeX refuses is repaired (text-mode and layout commands dropped, `\root…\of` → `\sqrt[…]`, glued font/size switches split off, unpaired `\left`/`\right` unsized, braces balanced), and no edit can fuse a control word with the next letter.
- **Scan furniture:** a line that is only a page number at the top or bottom 8% of a scanned page is dropped; a journal imprint (copyright with year, journal citation `VOL. n, a–b (yyyy)`, CCC/ISSN code) near the head or foot of a page is dropped.
- **Not done, by measurement:** voting with Apple Vision on macOS (its old-scans reading scored below PP-OCRv6 medium: 71.5 vs 78.5 fuzzy match on the "present" texts, 17.9% vs 27.9% of tests); a contrast-stretched second reading of low-confidence lines (no gain, one more page number leaked); routing every scan-with-layer page to the models (dropped a patent number in a page header with no quality gain). PP-FormulaNet stays blocked on training-data terms.
- **Removed after ablation** (each change switched off on its own, same benchmarks): reading tall boxes turned a quarter (no benchmark exercises it, and dropping it gained one old-scans test); dropping formula bold on scans that bold numerals (no effect); joining a sentence across a page-foot footnote (R1 97.1 without it, 96.0 with it). Kept because switching them off lost: KaTeX repairs (old scans math 47.6 → 46.9%, arXiv math 84.6 → 84.4%) and routing pages that spell formulas as loose letters (SLIDE_1 86.7 → 84.2). PP-OCRv6 small reads a scanned page about twice as fast (1.5 s vs 3.2 s on the M4 Pro, serial) but scores 26.0% on old scans against 29.3%, so medium stays the default.

**Result:** see the table below (M4 Pro; olmOCR-bench old scans: 98 PDFs / 526 tests; old scans math: 36 PDFs / 458 tests).

## 2026-10-15: Two flavours of every release, and the models through PyPI and npm

**Context:** the PDF vision models are about 510 MB. Some users want one download that just works, including offline and behind corporate firewalls. Others want the converter without them. Package registries limit file sizes (PyPI: 100 MB per file by default), and so do the company mirrors that sit in front of them. Until now the release offered only a lite binary plus a separate model archive, and nothing was published to PyPI or npm.

**Decision:**
- **GitHub releases carry both flavours.**
  - `filegoblin-<target>` is dist's lite build.
  - `filegoblin-full-<target>` is one binary with the models compiled in (`bundled-models`). It is built in `vision-models.yml` with link-time optimization off: half a gigabyte of embedded weights would make LTO slow and memory-hungry, for no speed gain. A test build took 111 s and peaked at 4 GB of memory.
  - The model archive is still attached on its own.
- **PyPI:**
  - `filegoblin` is one wheel per platform: the binary plus a small launcher.
  - `filegoblin[models]` adds `filegoblin-models`, which pulls in one package per model: `filegoblin-model-layout-1`/`-2`, `-formula-encoder`, `-formula-decoder`, `-tables-1`/`-2`, `-ocr-detector` and `-ocr-recognizer`.
- **npm:**
  - `filegoblin` is the launcher, and `@filegoblin/<os>-<cpu>` packages carry the binaries.
  - `@filegoblin/models` adds the weights through the same per-model packages, `@filegoblin/model-…`.
  - Everything except the launcher is in the `@filegoblin` scope, owned by the npm organisation `filegoblin`. With unscoped names, anyone could publish a not-yet-claimed name (a platform added later, or any of them before the first release), and `npm install filegoblin` would then run their binary.
- **The weights travel inside the registry packages** rather than being fetched at install or run time. Company mirrors usually proxy PyPI and npm but block github.com. pip has no post-install hooks, and npm install scripts are often disabled.
- **One package per model, named for what it does.** The two models over the 100 MB limit, layout (134 MB) and tables (118 MB), come in equal halves (`-1`, `-2`) whose files are named `<model>.part<i>of<n>`. The model loader joins them in memory, and the halves may sit in different directories (on npm they do). The splits are fixed in `scripts/package_registries.py` (`MODEL_PACKAGES`) so the package names never change, and the build fails if a model outgrows its split. An earlier layout bin-packed anonymous 90 MiB pieces into `models-part1…6`; it was replaced before any release because the names said nothing about the contents.
- **`FILEGOBLIN_MODELS` takes a `PATH`-style list.** The pip and npm launchers append the model package's directories to it, after any directory the user set.
- **`--install-models [DIR]`** downloads this version's model archive from the GitHub release, checks its SHA-256 against the published `.sha256`, and unpacks it into `~/.filegoblin/models`. `FILEGOBLIN_MODELS_URL` points it at a mirror or at a local file. filegoblin never downloads models on its own.
- **`--models-status`** shows where each model is found.
- **Publishing** uses trusted publishing (OIDC) on both registries, with no stored tokens: PyPI trusts `publish.yml` with environment `pypi`, and npm trusts `publish.yml` with environment `npm`. One workflow serves both registries, with one environment per registry.
  - It is a separate top-level workflow, started when a tag run of Release succeeds, rather than a dist publish job. dist publish jobs are reusable workflows, and PyPI's trusted publishing does not work from those (pypa/gh-action-pypi-publish#166).
  - npm cannot configure a trusted publisher for a package that does not exist yet. `scripts/npm-bootstrap.sh` publishes a deprecated placeholder for each new `@filegoblin/…` name, then runs `npm trust github` for every package. Setup is in docs/RELEASING.md.

**Verified locally**, with the Linux x86_64 build and the real model archive:
- `pip install "filegoblin[models]"` from the built wheels and `npm install filegoblin @filegoblin/models` from the packed tarballs both found all nine models.
- Both produced output byte-identical to a run with the models read straight from disk.
- The lite installs report the models missing.
- `--install-models` works over HTTP and from a local file.

The CI workflows pass actionlint (one new runner label is not in its list yet), and `dist plan` passes. The release pipeline itself still has to run on a real tag: no release has completed yet, because the last attempts (v1.13.0, v1.14.0) failed on a dist configuration error that has since been fixed.

**Status:** Accepted.
